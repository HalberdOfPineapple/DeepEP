Each folder holds the scripts, the raw results (results/*.pt or .json), the logs, and a self-contained report.html with motivation, method, results and diagrams. common/README.md documents the tooling: a private copy of the installed DeepEP package with an instrumented dispatch kernel, a per-lane trace smuggled out through an existing tensor pointer, and in-run cross-GPU clock calibration.

E2Does a hot destination slow a sender's stores to idle destinations?Yes, through the sender's own per-SM FIFO: per-destination latency is identical for hot and idle destinations at every ratio, the hot rank's intake caps near 320 GB/s, and idle destinations' stores stretch over the whole kernel instead of finishing early. Releasing the slot earlier (wait_group.read) changes nothing.E2 report
E3Do ~15,000 returning atomics on one 32-byte sector cost anything?No: 96 ns p50 and ≤128 ns p99 with or without padding, kernel time unchanged. A non-problem at four ranks; worth repeating at eight and beyond.E3 report

A GPU-side delay under ~85 µs is hidden behind the host launch path; beyond that the peers idle one for one. Host stamps tell a busy GPU from a slow host.E6 report

What changed in the analysis after measuring

  • Sender-side per-token delivery is unobservable (note challenge C2): the sender's only per-token event reports local acceptance; the sensor for the peer is a system-scope release, which costs a round trip. Receiver-side arrival stays unobservable in software.
  • Throughput bound rewritten (note problem P2): the limit on how far a warp runs ahead is the per-SM async-proxy queue, not one token per warp per round trip; throughput is per-SM drain × SMs up to the per-GPU NVLink plateau; back-pressure appears first on the store instruction.
  • Incast victim flows sharpened (note problem P1): the victim-flow effect exists and is produced upstream of the link, in the sender's shared FIFO; switch-level sharing is not needed to explain the data and is not excluded.
  • Slot-counter hotspot downgraded (note problem P3) at four ranks; the measurement to repeat at scale is in E3.
  • Clock synchronisation: a single ping-pong calibration closes triangles to ~100 ns, but the GPUs' %globaltimer clocks drift by milliseconds per hour against each other, so calibration must bracket each measured kernel (about 12 ms for four ranks). The note's "once per session" is withdrawn.
  • Tooling result: a per-lane trace with 0.1–1 % overhead, written through an existing kernel argument, is enough for E0–E9; the library knows every store's destination, so address-classified accounting comes for free.
  • New after E5–E9 (phase attribution): the frame's green phases (A, B, C, E, F) are decomposed end to end, including the host path, with one clock across ranks; the dark phase D gained one attributable location, the sender's TPC (E7), and one attributable cause, a foreign kernel on the links, visible only through counters outside the kernel (E8).
  • The observer is part of the system: host-side counter reads (NVML) and cooperative-launch scheduling both perturb sub-millisecond kernels by more than the effects under study; a tool has to read from the GPU or place its reads where they have decayed.
